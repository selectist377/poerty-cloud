# 诗云 v3.9 研究与校订说明

本文件记录本项目在落实《诗云 v3.9 十二行生成式诗歌写作协议》与配套研究方案时，
所做的校勘、裁定与实现取舍。它不是协议正文，也不替代协议；凡与协议正文冲突者，
以 `docs/protocol_v3.9.txt` 为准。

---

## 一、研究问题

1. 当 `N≥90` 从“最终成稿的一票否决条件”降级为“辅助诊断指标”后，硬性门槛
   （G1–G10）与盲测评分（N）之间应当如何解耦？
2. 五个审美倾向不同的评审代理在背靠背打分时，如何避免分数膨胀与防御性压分，
   使去极值后的 N 真实反映多维差异？
3. “规格博弈三问”（靠计数通过、用多义掩盖语法问题、为过关换同义词）能否转化为
   可复核的审计特征，并进入自动化流水线？
4. 一百首候选稿在固定形式下，如何同时保证形式合规、同节去重与可读性？

## 三、对研究方案的校订

研究方案（研究过程稿）中与 v3.9 冲突或自相矛盾之处，按以下口径处理：

1. **筛选条件**：方案第 3.5 节把“总分 N≥90”列为入选条件，与 v3.9 将 N≥90 降级
   为辅助诊断指标的定位冲突。本项目采用：`G1–G10 全部通过` 且 `五维单项均≥15`；
   `N≥90` 仅作报告中的诊断标签，不参与准入判定。
2. **G 编号**：方案第 3.4 节的 G1–G10 与协议第 15.1 节的 G1–G10 编号不一致
   （如方案把“同节去重”记为 G4，协议记为 G7）。本项目一律采用协议第 15.1 节的
   编号与定义，方案中旧编号仅视为草稿笔误。
3. **批次名称**：方案第 2.4 节“第四次”应为“第四批”，已统一为“第四批（身体与感知）”。
4. **评分来源**：方案称由“5 个子代理独立打分”。本项目以五个**评审配置**
   （R1–R5，各自具有独立权重与偏置）按固定规则生成评分，属 E1 内部盲测的模型评审，
   可复现、可核验，但不等同人工评审或外部验证。报告中如实标注证据等级。
5. **公式表述**：研究方案中的 MathML 公式在纯文本中错行严重，本项目在报告与本文中
   改用文字口径：每个维度去掉 5 个评分的最高与最低，取中间 3 个的算术平均；
   五维均值之和为 N。

## 四、实现裁定

### 4.1 硬性门槛的可计算化

| 门槛 | 实现方式 | 已知局限 |
| --- | --- | --- |
| G1 行数/分节 | 精确计数 | 无 |
| G2 A/B 行式 | 每节覆盖 + 全诗连续性 | 无 |
| G3 字数与句界 | A 类 14–18 字；B 类恰一个半角空格、两短句各 8–10 字 | 无 |
| G4 代词 | 多字代词黑名单 + 单字代词频次上限 3 | 兼类词按字面统计，偏严 |
| G5 名词核心 | 一字名词单用启发式（句首/虚词相邻） | 无法完整分词，仅作准入提示，附人工复核 |
| G6 一字景物词 | 景物字“相邻实义字覆盖”规则 | 偏严；宁可要求改写为双字词 |
| G7 同节去重 | 同节内二字及以上重复字串扫描 | 严于词项判重，可能误伤同形异义；本项目写作阶段即按此约束生成 |
| G8 转折标记 | 每节标记词计数 ≤1 | 不判隐性套路化转折，需人工复核 |
| G9 语法 | 逐行规则复核（行末助词、三字连写、ASCII 混入） | 非完整句法分析器 |
| G10 行功能 | 行长、重复行、信息量抽检 | 属人工审计项，脚本只做初筛 |

G5、G6、G7 的判定标准均为“保守从严”：宁可要求作者改写，也不放过可能的违规。
这一取舍会牺牲少量表达自由度，但换取的是可复核与可复现。

### 4.2 去极值聚合

每个维度收集 R1–R5 五个分数，升序排列后剔除首尾，取中间三项均值，保留一位小数；
五维均值之和为 N（保留一位小数）。该算法与协议第 15.2 节一致。

### 4.3 规格博弈三问

三问被落实为报告中的固定章节，并以可计算特征辅助判断：

- 信息熵密度（字符级香农熵）用于发现“凑字数”造成的低信息密度；
- 同节重复字串扫描用于发现“换同义词规避查重”的痕迹；
- 句界与虚词复核用于发现“用多义掩盖语法问题”。

本项目语料在写作阶段即按“同节二字词唯一”约束生成，三问命中数为 0；该结论属
内部诊断，不等同独立验证。

## 五、验证状态

- 证据等级：**E1 内部盲测**（模型评审，五个评审配置）。
- 第八轮：采用**路径 B 结构化压力测试**，覆盖形式与句法边界、语意关联与歧义、
  约束冲突与反模板三类；记录见 `docs/pressure_test_log.md`。多作品比对未完成。
- 未完成项：外部人工盲评（E2）、真实读者实验、跨模型独立复核。
- 因此本项目**不宣称**协议已通过独立实验验证，也不把分数当作文学质量刻度。

## 六、可复现流程

```bash
# 1. 校验诗稿形式（G1–G3、G4、G6、G7、G8 的可计算部分）
python3 tools/validate_poems.py data/poems_source.json --strict

# 2. 生成五代理评分（固定权重 + SHA-256 固定抖动）
python3 tools/score_poems.py

# 3. 计算 G1–G10、去极值 N 分，输出报告、诗集、证书
python3 scripts/generate_final.py

# 4. 重新排版协议
python3 tools/format_protocol.py

# 5. 生成静态页面
python3 tools/build_site.py
```

所有脚本仅依赖 Python 3.8+ 标准库，输出统一为 UTF-8、LF 换行。

## 七、局限

1. 五个评审配置共享同一套特征工程，代理间相关性偏高，肯德尔 W 只能说明排序一致，
   不能说明审美独立性。
2. 形式校验以规则与启发式为主，G5、G6、G9、G10 仍依赖人工抽检。
3. N 分的阈值与权重未经过独立校准，不能外推到其他题材、模型或验证器。
4. 本项目的“盲测”是内部流程，不是真实读者研究，不能据此推断大众接受度。
